# Albion Guidewire modernisation — executive briefing UI

A five-screen briefing for the board and executive team. Every figure is read from this repository; nothing is typed in
by hand. Panels for the next phases (shadow run, reconciliation, cutover) are labelled **Planned** and stay empty until
their evidence is committed.

| # | Screen | What it shows |
|---|---|---|
| 01 | Executive overview | Headline estate figures, the four-phase roadmap, what Phase 1 delivers, release-gate results, brands, recorded structural risks |
| 02 | Estate control tower | The four platforms, all 18 interfaces with a brand × environment cutover grid, Control-M schedule, environments and vault secrets |
| 03 | Business journeys | The documented end-to-end journeys and the shared feed-status field they depend on |
| 04 | Shadow run & cutover | The Phase 2/3 plan, today's record layout per interface, and the (empty) shadow-run and reconciliation result panels |
| 05 | Dashboards | Interface volumes, rules by purpose, transport and batch mix, test fixtures, code and tests, and the Phase 2/3 scorecard |

## Run it

Requires Node.js 18.18+ (tested with 20 and 24) and Python 3.

```bash
cd demo-ui
npm ci
npm run dev        # http://localhost:5173
# or a production build:
npm run build && npm run preview   # http://localhost:4173
```

Use ← / → or the top navigation to move between screens; each screen has its own URL hash (`#overview`, `#estate`,
`#journeys`, `#shadow`, `#dashboards`).

## Where the numbers come from

`src/data/repo-facts.json` is generated by `scripts/collect_repo_facts.py` (Python 3 standard library only):

```bash
npm run facts      # = python3 scripts/collect_repo_facts.py
```

The script reads the committed tree and runs both repository checks:

| Figure | Source |
|---|---|
| Platforms, rules, rule sets, rule families | `*/config/rules/**/*.grs`, `*.gr` |
| Activity patterns | `*/config/import/gen/albion-activity-patterns.xml` |
| Screens, code modules, unit tests, data extensions, encrypted columns | `*.pcf`, `gsrc/**/*.gs`, `gtest/**/*Test.gs`, `*.etx`/`*.eti` per platform |
| Connector plugins, outbound channels | `*/config/plugin/registry/*.gwp`, `*/config/messaging/*.xml` |
| Interfaces, volumes, transport, record layout, error handling | `docs/interfaces/interface-contract-inventory.csv` and the interface specifications |
| Reference messages | `integration/samples/<interface>/` |
| Batch jobs, servers, on-request jobs | `batch/controlm/*.xml`, `batch/jcl/`, `batch/jcl/adhoc/` |
| Environments, templates, vault secrets | `environments/*/*.template` |
| Brands and mainframe codes | `integration/polaris/mappings/brand_xref.csv` |
| Release-pipeline stages | `Jenkinsfile` |
| Brand consistency result | `python3 tools/scripts/check_brand_config_drift.py` |
| Estate coherence result | `python3 tools/scripts/check_gw_coherence.py .` |
| Journeys | `docs/business-journeys/*.md` |
| Feed-status consumers (documented baseline) | `docs/architecture/FEEDSTATUS-STATE-MACHINE.md` |
| Structural risks, reconciliation tolerance | `docs/architecture/estate-overview.md`, `docs/architecture/CONTROLS-AND-TOLERANCES.md` |

Re-run `npm run facts` after the repository changes and commit the regenerated JSON. The coherence check is run against
a temporary copy of the git-tracked files, so a local `node_modules/` does not affect the result.

## Wiring in Phase 2/3 evidence

`src/data/evidence.ts` merges every `src/data/evidence/*.json` at build time. Each file follows `EvidenceFile` in
`src/data/types.ts`:

```json
{
  "shadowRuns": [{ "interfaceId": "IF-MID-001", "brand": "ALBDIR", "environment": "sit",
                   "windowStart": "…", "windowEnd": "…", "recordsCompared": 0, "mismatches": 0, "source": "…" }],
  "reconciliation": [{ "control": "…", "environment": "sit", "period": "…", "status": "MATCHED", "source": "…" }],
  "cutover": [{ "interfaceId": "IF-MID-001", "brand": "ALBDIR", "environment": "dev", "authority": "SHADOW",
                "since": "…", "source": "…" }]
}
```

With no files present (today), the shadow-run, reconciliation and cutover panels show an explicit "not committed yet"
state and every feed is shown on the current code.

## Repository checks and `node_modules`

`tools/scripts/check_gw_coherence.py .` scans every file under the repository root. Third-party packages installed in
`demo-ui/node_modules/` contain strings it treats as findings, so run the repository checks on a clean checkout (as the
release pipeline does) or after `rm -rf demo-ui/node_modules demo-ui/dist`.

## Stack
